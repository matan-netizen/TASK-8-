## A07 + A04: התחזות למנהל עם עוגייה מזויפת (קריטי)

**הבעיה:** אחרי הכניסה נשמר בעוגייה רק מזהה המשתמש (`demo_user=m1`). השרת האמין לעוגייה בלי שום בדיקה, ולכן כל אחד יכול לכתוב את העוגייה לבד ולקבל גישת מנהל: לראות משימות, הערות פרטיות ומאגר מידע של לקוחות. בנוסף, העוגייה לא סומנה `Secure` ולא היה לה תוקף.

**הוכחה (לפני):**
```bash
curl -b "demo_user=m1" http://localhost:3000/api/notifications
# {"notifications":[]}   ← גישת מנהל בלי להתחבר
```

**התיקון** (`src/lib/session.ts`):
- העוגייה חתומה עכשיו ב-**HMAC-SHA256** עם סוד שנמצא רק בשרת (`SESSION_SECRET`): `userId.expiry.signature`.
- ההשוואה נעשית ב-`timingSafeEqual`, כדי שאי אפשר יהיה לנחש את החתימה לפי זמני תגובה.
- תוקף של 8 שעות, ודגלים `HttpOnly`, `Secure` (בייצור) ו-`SameSite=Strict`.
- אם לא הוגדר סוד, המערכת יוצרת סוד אקראי (fail-safe), כך שעוגייה מזויפת אף פעם לא תתקבל.
- **קוד גישה** אופציונלי (`ACCESS_CODE`): אם הוא מוגדר, מסך הכניסה דורש אותו. מומלץ בייצור, כי עד עכשיו כל מי שהכיר את הכתובת נכנס.

**הוכחה (אחרי):**
```bash
curl -b "demo_user=m1" http://localhost:3000/api/notifications
# {"error":"יש להתחבר כדי להמשיך"}
```
```
set-cookie: demo_user=m1.1795625327.6QE4iA_…; Max-Age=28800; Secure; HttpOnly; SameSite=strict
```

**בדיקות:** עוגייה ישנה, החלפת מזהה עובד במנהל, הארכת תוקף, עוגייה שפג תוקפה וקלט זבל, כולן נדחות.

## A01: CSRF (בקשות מאתר זר)

**הבעיה:** אתר זדוני יכול היה לשלוח בקשת POST לשרת שלנו מתוך הדפדפן של המשתמש.

**הוכחה (לפני):**
```bash
curl -X POST -H "Origin: https://evil.example" -d '{"userId":"m1"}' .../api/session
# HTTP/1.1 200 OK + set-cookie
```

**התיקון** (`src/proxy.ts`): כל בקשה שמשנה מצב (POST/PATCH/DELETE) ל-`/api` נבדקת: אם הכותרת `Origin` שונה מהכתובת שלנו, הבקשה נחסמת ב-403. בנוסף, העוגייה היא עכשיו `SameSite=Strict`.

**אחרי:** `HTTP/1.1 403 Forbidden · {"error":"בקשה ממקור לא מורשה"}`

## A02: כותרות אבטחה

**הבעיה:** השרת החזיר רק `X-Powered-By: Next.js`, ולא החזיר אף כותרת הגנה.

**התיקון** (`next.config.ts`):

| כותרת | מגינה מפני |
|---|---|
| `Content-Security-Policy` | הרצת סקריפטים זרים (XSS), חיבור לשרתים זרים |
| `X-Frame-Options: DENY` + `frame-ancestors 'none'` | Clickjacking (הטמעת האתר בתוך iframe) |
| `X-Content-Type-Options: nosniff` | ניחוש סוג קובץ על ידי הדפדפן |
| `Referrer-Policy` | דליפת כתובות לאתרים אחרים |
| `Permissions-Policy` | גישה למצלמה, למיקרופון ולמיקום |
| `Strict-Transport-Security` (בייצור) | הורדה ל-HTTP לא מוצפן |

וגם `poweredByHeader: false`.

**פשרה ידועה:** Next.js מזריק סקריפטים מוטמעים (inline), ולכן ה-CSP כולל `'unsafe-inline'`. השלב הבא הוא CSP עם nonce.

## A05: הזרקת הוראות ל-AI (Prompt Injection) דרך מסמך

**הבעיה:** קטעים ממאגר המידע נשלחים למודל בתוך `<knowledge>`, עם הנחיה שהתוכן הוא "נתונים בלבד". אבל מסמך שמכיל את הטקסט `</knowledge>` יכול לסגור את התגית מוקדם, ואז ההוראות שאחריו נראות למודל כאילו הן מחוץ לאזור הנתונים.

**התיקון** (`neutralizeTags` ב-`src/lib/knowledge.ts`): תגיות `knowledge`/`document` שמופיעות בתוך מסמך מנוטרלות (`<` הופך ל-`‹`), וגם כותרת ושם פרויקט מנוקים. התוכן נשמר, ורק היכולת "לברוח" מהתגית נעלמת.

**נבדק ולא נמצאה בעיה:** אין SQL. כל הקלט עובר ולידציה ב-zod. React מבצע escaping לכל הטקסט, ואין `dangerouslySetInnerHTML`. אין `eval` או `exec`.

## A06: הגבלת קצב (עלויות AI וניחוש קוד גישה)

**הבעיה:** כל יצירת משימה וכל הודעה בצ'אט הן קריאה בתשלום ל-Anthropic, בלי הגבלה (OWASP LLM10: Unbounded Consumption). גם מסך הכניסה לא הוגבל, כך שאפשר היה לנחש קוד גישה.

**התיקון** (`src/lib/rate-limit.ts`):
- עד 30 קריאות AI לדקה לכל משתמש (`AI_RATE_LIMIT_PER_MIN`). התשובה מעבר למגבלה היא 429 עם הודעה בעברית.
- עד 10 ניסיונות התחברות לדקה לכל כתובת IP (`LOGIN_RATE_LIMIT_PER_MIN`).
- ההגבלה נבדקת **אחרי** בדיקת ההרשאות, כך שבקשות לא מורשות לא "שורפות" למשתמש את המכסה.

**אחרי:** 12 ניסיונות התחברות ברצף החזירו `200 ×9`, ואחריהם `429 429 429`.

## A03: שרשרת אספקה

- `npm audit` מצא פגיעות בינונית ב-`uuid` (ספרייה שנכנסת דרך `exceljs`). התיקון היה `overrides` ל-`uuid@^11.1.1`, והתוצאה: **0 vulnerabilities**. וידאתי שקריאת קבצי Excel במאגר עדיין עובדת (בדיקות `knowledge`).
- נוסף `.github/dependabot.yml` לעדכוני תלויות שבועיים (npm ו-GitHub Actions).
- ה-CI מריץ עכשיו `npm run audit` ונכשל אם יש פגיעות.

## A09: רישום אירועי אבטחה

נוספה הקידומת `[security]` ביומנים עבור: התחברות מוצלחת, קוד גישה שגוי, חריגה ממגבלת קצב, בקשה ממקור זר, וכל תשובת 401/403/429. היומן לא כולל תוכן של משימות או סיסמאות. ראו גם [manage.md](manage.md).

## A08 ו-A10: נבדקו

- **A08:** התקנה עם `npm ci` לפי lockfile, וכתיבה אטומית למסד הנתונים (קובץ זמני ואז החלפה). בנוסף הוגדר `permissions: contents: read` ב-CI, כך שה-workflow לא יכול לכתוב לריפו.
- **A10:** `handle()` מחזיר "אירעה שגיאה בשרת" בלי פרטים פנימיים. JSON פגום מחזיר 400. כשל של מאגר המידע או של ה-AI לא מפיל את התהליך, אבל גם לא פותח גישה: בדיקות ההרשאה רצות לפני כל דבר אחר.
