## 1. רקע ומטרה

היום מסך המנהל (`/manager`) כולל טופס ליצירת משימה ורשימת משימות עם סינון לפי סטטוס. אין בו תמונת מצב: כמה משימות פתוחות, מי מהעובדים עמוס, מה מתעכב ומה הושלם לאחרונה.

**מטרת הדשבורד:** לתת למנהל, במבט אחד, תמונת מצב של המשימות והצוות, ולהוביל אותו לפעולה הבאה הנדרשת (לשייך טיוטה, לענות על שאלה פתוחה, לבדוק משימה שהושלמה).

### מדדי הצלחה למסך
- המנהל מזהה תוך פחות מ-10 שניות אילו משימות דורשות ממנו פעולה.
- כל מספר בדשבורד לחיץ ומוביל לרשימה המסוננת שמאחוריו.
- הדשבורד נטען תוך פחות מ-2 שניות עם עד 500 משימות.

## 2. משתמשים והרשאות

| תפקיד | גישה לדשבורד | מה רואה |
|---|---|---|
| מנהל | כן | רק משימות שהוא יצר, והעובדים שקיבלו ממנו משימות |
| עובד | לא | ניסיון גישה מפנה למסך "המשימות שלי" |

- הנתונים מסוננים **בצד השרת** לפי המנהל המחובר, כמו בשאר ה-API הקיים (`managerId`).
- הערות פרטיות של המנהל ותוכן הצ'אטים **לא** מוצגים בדשבורד, רק ספירות.

## 4. רכיבי המסך

### 4.1 כרטיסי מדדים (שורה עליונה)

| כרטיס | חישוב | לחיצה מובילה אל |
|---|---|---|
| **טיוטות** | `status = draft` | רשימת משימות מסוננת: טיוטות |
| **בביצוע** | `status = assigned` | רשימת משימות מסוננת: בביצוע |
| **בוצעו** | `status = completed` בטווח הזמן שנבחר | רשימת משימות מסוננת: בוצעו |
| **דורש תשומת לב** | מספר הפריטים ברשימה 4.2 | גלילה לרשימה 4.2 |

- מתחת לכל מספר: שינוי לעומת התקופה הקודמת באותו אורך (למשל "+3 מהשבוע שעבר"). מוצג רק אם יש נתונים לתקופה הקודמת.
- טווח הזמן משפיע רק על "בוצעו" ועל "פעילות אחרונה". טיוטות ומשימות בביצוע מוצגות תמיד במצבן הנוכחי.

### 4.2 דורש את הפעולה שלך

רשימה ממוינת לפי דחיפות. כל שורה: כותרת המשימה, סיבה, עובד (אם יש), ותאריך.

| סיבה | תנאי | פעולה מוצעת |
|---|---|---|
| טיוטה שלא שויכה | `status = draft` | כפתור "לשיוך" |
| שאלות הבהרה פתוחות | `clarificationQuestions` לא ריק ו-`status = draft` | כפתור "להשלמת פרטים" |
| הושלמה ולא נצפתה | יש התראת "בוצע!" שלא נקראה | כפתור "לצפייה" (מסמן כנקרא) |
| עדיפות גבוהה בביצוע | `priority = high` ו-`status = assigned` | קישור למשימה |

סדר המיון: הושלמה ולא נצפתה, ואחריה עדיפות גבוהה, שאלות פתוחות וטיוטות. בתוך כל קבוצה, הישנה ביותר קודם.
מוצגות עד 8 שורות, ואחריהן קישור "הצג הכל".

> **הערה:** במערכת היום מועד היעד נשמר כטקסט חופשי ("עד יום חמישי"), ולכן אי אפשר לחשב "באיחור". ראו שאלה פתוחה 1.

### 4.3 עומס לפי עובד

טבלה, שורה לכל עובד:

| עמודה | חישוב |
|---|---|
| שם העובד | |
| בביצוע | מספר משימות `assigned` |
| מתוכן בעדיפות גבוהה | `assigned` ו-`priority = high` |
| בוצעו בטווח | `completed` בטווח הזמן שנבחר |
| פעילות אחרונה | התאריך העדכני מבין: השלמה אחרונה או הודעת צ'אט אחרונה של העובד |

- פס התקדמות לכל עובד: בוצעו מתוך (בוצעו + בביצוע) בטווח שנבחר.
- לחיצה על שורה פותחת את רשימת המשימות מסוננת לפי העובד.
- מיון ברירת מחדל: הכי הרבה משימות בביצוע למעלה.
- הדשבורד **לא** משווה בין עובדים ולא מדרג אותם. הטבלה נועדה לחלוקת עומס, לא להערכת ביצועים.

### 4.4 פעילות אחרונה

ציר זמן של עד 10 אירועים אחרונים בטווח שנבחר:
- משימה נוצרה
- משימה שויכה לעובד
- **בוצע!** (משימה הושלמה), מודגש בירוק
- עובד פתח שיחה בצ'אט במשימה (רק "שאל שאלה", בלי תוכן ההודעה)

כל אירוע לחיץ ומוביל למשימה.

### 4.5 התפלגות עדיפויות

תרשים עמודות אופקי למשימות פתוחות (טיוטה + בביצוע) לפי עדיפות: גבוהה, בינונית, נמוכה, לא צוינה.
אם אין משימות פתוחות, התרשים לא מוצג ובמקומו מופיעה הודעת מצב ריק.

## 8. ממשק נתונים (API)

נקודת קצה חדשה אחת, שמחזירה את כל נתוני הדשבורד בקריאה אחת:

```
GET /api/dashboard?range=7d
```

**הרשאה:** מנהל בלבד (401 למשתמש לא מחובר, 403 לעובד).

**תשובה:**
```json
{
  "range": "7d",
  "generatedAt": "2026-11-04T09:00:00.000Z",
  "counts": {
    "draft": 2,
    "assigned": 5,
    "completedInRange": 7,
    "completedPrevRange": 4,
    "needsAttention": 3
  },
  "needsAttention": [
    {
      "taskId": "…",
      "title": "…",
      "reason": "completed_unseen | high_priority | open_questions | unassigned",
      "assigneeName": "…",
      "since": "…"
    }
  ],
  "workload": [
    {
      "employeeId": "e1",
      "name": "…",
      "assigned": 3,
      "assignedHigh": 1,
      "completedInRange": 4,
      "lastActivityAt": "…"
    }
  ],
  "activity": [
    { "type": "created | assigned | completed | employee_asked", "taskId": "…", "title": "…", "at": "…" }
  ],
  "priorityBreakdown": { "high": 2, "medium": 1, "low": 0, "none": 4 }
}
```

**מימוש:**
- פונקציה חדשה `getDashboard(user, range)` ב-`src/lib/services.ts`, באותו דפוס של שאר השירותים (בדיקת תפקיד, `read` מה-store).
- כל החישובים בצד השרת. לא נשלחים לדפדפן תוכן הודעות צ'אט, הערות פרטיות או הבקשה המקורית.
- בדיקת קלט ל-`range` עם zod. ערך לא חוקי מחזיר שגיאה 400 בעברית.
- "התקופה הקודמת": אותו אורך, מיד לפני הטווח הנבחר. בטווח "הכל" לא מחושבת השוואה.

**שינויים במודל הנתונים:** אין שינויים נדרשים. כל הנתונים זמינים כבר היום (`createdAt`, `assignedAt`, `completedAt`, `priority`, `clarificationQuestions`, ההתראות והודעות הצ'אט).

## 9. ניווט

- הדשבורד הופך למסך הבית של המנהל אחרי הכניסה.
- בכותרת העליונה של המנהל נוספים קישורים: **דשבורד** · **משימות** · **משימה חדשה**.
- המסך הקיים `/manager` נשאר כמסך "משימות". הוא מקבל פרמטרים בכתובת (`?status=`, `?assignee=`), כדי שהלחיצות מהדשבורד יפתחו אותו מסונן.

## 10. נגישות ושפה

- כל הטקסטים בעברית, `dir="rtl"`. מספרים ותאריכים בפורמט `he-IL`.
- לכל כרטיס מדד יש `aria-label` מלא (למשל "5 משימות בביצוע").
- התרשים כולל גם טבלת נתונים חלופית לקוראי מסך.
- צבע הוא לא האמצעי היחיד להעברת מידע: לכל סטטוס יש גם טקסט.
- ניגודיות לפי WCAG AA.

## 11. קריטריונים לקבלה

1. מנהל שנכנס למערכת מגיע לדשבורד ורואה ארבעה כרטיסי מדדים עם מספרים נכונים.
2. כל מספר בכרטיס מדד שווה למספר המשימות שמופיעות ברשימה המסוננת אחרי לחיצה עליו.
3. אחרי שעובד מסמן משימה כבוצעה, תוך 5 שניות לכל היותר: "בוצעו" עולה ב-1, "בביצוע" יורד ב-1, והמשימה מופיעה ב"דורש את הפעולה שלך" עם הסיבה "הושלמה ולא נצפתה".
4. לחיצה על "לצפייה" מסמנת את ההתראה כנקראה, והפריט יוצא מהרשימה.
5. מנהל לא רואה בדשבורד משימות של מנהל אחר.
6. עובד שמנסה לגשת ל-`/api/dashboard` מקבל 403, ול-`/manager/dashboard` מופנה למסך שלו.
7. תשובת ה-API לא כוללת `managerNotes`, `rawDescription` או תוכן הודעות צ'אט.
8. מצבי טעינה, ריק ושגיאה מוצגים כמתואר בסעיף 6.
9. המסך תקין ברוחב 375px בלי גלילה אופקית.
10. בדיקות אוטומטיות (vitest) מכסות את `getDashboard`: ספירות, טווחי זמן, הרשאות ואי-חשיפת שדות פרטיים.

## 13. שאלות פתוחות להחלטה

1. **מועד יעד כתאריך:** היום המועד נשמר כטקסט חופשי. כדי להציג "באיחור" ו"מתקרב למועד", צריך להוסיף שדה תאריך (למשל `dueDate`) לצד הטקסט. להוסיף אותו בגרסה זו או בגרסה הבאה?
2. **"דורש תשומת לב":** האם רשימת התנאים בסעיף 4.2 מספיקה, או שיש מצבים נוספים שחשוב לך לראות?
3. **טווח ברירת מחדל:** 7 ימים מתאים, או שעדיף "היום"?
4. **שאלות של עובדים בצ'אט:** האם להציג למנהל שעובד שאל שאלה בצ'אט (בלי התוכן)? זה עוזר לזהות עובד שתקוע, אבל עלול להרגיש כמו מעקב.
5. **ריבוי מנהלים:** האם מנהל צריך לראות גם משימות של מנהלים אחרים בצוות, או רק את שלו (כמו היום)?
